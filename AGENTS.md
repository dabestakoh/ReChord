# ReChord agent instructions

Read the [ReChord engineering standards](docs/RECHORD-STANDARDS.md) before planning or editing. It is the canonical guide for coding, UI, playback, add-ons, and delivery. When assessing or syncing upstream BitChord updates, also read the [ReChord upstream sync policy](docs/UPSTREAM-SYNC-POLICY.md) to avoid pulling intentionally omitted features.

- Keep planning and investigation read-only until the user approves implementation.
- Load `rechord-multi-agent-orchestration` (along with `rechord-compose-perf-audit` for UI and `rechord-preview-and-release` for delivery) to save main-context tokens: offload broad code/locale scouting (`rechord-code-scout`) and Gradle/CI verification (`rechord-verifier`) to `flash` or `flash_lite` subagents returning compact `<250-token` line-range summaries, reuse warm subagents via `send_message`, skip subagents for trivial known-line edits, and reserve `pro` subagents for complex multi-file domain audits.
- Treat Portrait and Landscape — including cutout/gesture phones (rotated both ways), 3-button-nav phones, DAPs (`560–720 × 360 dp`), Car Head-Units (`640 × 360 dp`, `800 × 480 dp`, `853 × 480 dp`, `1024 × 600 dp`, `1280 × 720 dp`), and Tablets — as equal first-class targets in every UI, design, logic, and animation change. Before presenting any `/plan` or pushing a Preview APK, proactively audit: (1) horizontal safe-area insets (`navigationBars ∪ displayCutout`) across both the main Activity root and every separate `ModalBottomSheet` / `Dialog` window so no control ever crosses system bars or punch-holes in landscape; (2) full-width scrims and tap guards so they never dim or swallow touches on side rails (such as the A–Z index); (3) Portrait non-regression when fixing Landscape (and vice versa); and (4) synchronous Frame-1 state/scroll updates (`requestScrollToItem`, state holders) vs. delayed `LaunchedEffect` / `withFrameNanos` flashes, touch hitboxes, row text boundaries, and per-frame GPU/shader allocations.
- Work on the current or explicitly named branch. Ask before creating or switching branches. Merge and run release workflows only as authorized.
- Preserve existing app data, package identities, signing keys, audio behavior, and compatibility with query-only add-ons. Verify affected entry points and module builds (`:sharedUi:jvmTest`, `:sharedUi:compileDebugKotlinAndroid`, `:app:compileDevDebugKotlin`, `:tv:compileDevDebugKotlin` when shared code or `BuildConfig` fields affect TV, and `:app:testDevDebugUnitTest --tests "com.music.bitchord.LocaleStringsTest"` when adding/changing string keys) before reporting completion. Always upload Preview APKs directly as a single unzipped `.apk` (`actions/upload-artifact@v7` with `archive: false`), never wrapped in a `.zip`.
- Follow the approved scope and report what was verified. Write release notes (`docs/releases/v<version>.md`) in clear, non-technical, user-friendly language (noting the upstream BitChord base version when applicable), and when authorized to release on `main`, monitor all triggered release workflows to completion and fix any build/test issues. For documentation-only changes, skip push-triggered builds (`[skip ci]`) unless requested.
