# ReChord engineering standards

Use these standards when planning or implementing ReChord changes. They capture settled project decisions about coding, UI, playback, discovery, and delivery. Update this guide when a later approved change supersedes a lasting decision. Keep temporary investigations and version-specific details in their own notes. For upstream BitChord syncs, follow [UPSTREAM-SYNC-POLICY.md](UPSTREAM-SYNC-POLICY.md) so intentionally omitted features are never pulled back in and ReChord's own implementations take precedence. The current approved feature plan defines the scope for each task.

## Coding

- **Investigate before editing.** Trace the normal entry point, state owner, callers, and recovery path. Use the relevant platform or library documentation for integrations. Diagnose intermittent issues with logs or reproduction where possible. Keep confirmed behavior and hypotheses clear.
- **Keep the change small and complete.** Reuse existing Compose components, repositories, indexes, caches, playback queues, and settings patterns. Preserve other consumers of shared code. Avoid dependencies, architecture changes, cleanup, or extra features outside the approved scope.
- **Preserve compatibility.** Consider upgrades with existing settings, indexes, playlists, history, cache records, and restored playback. Use stable IDs for persisted choices where available. Make migrations safe to retry and retain fallbacks for older data. Keep identifiers needed by installed apps, backups, invite links, and device pairing. Use ReChord in user-facing copy and retain upstream credits. Check [UPSTREAM-SYNC-POLICY.md](UPSTREAM-SYNC-POLICY.md) before porting any upstream BitChord change.
- **Make asynchronous state safe.** Bound network fan-out, reuse work, and cancel obsolete requests. Guard late results with the active account, route, or playback identity as appropriate. Retain valid cached data through transient failures and isolate optional work from the primary operation.
- **Verify the regression.** Run the closest existing checks and add focused coverage where the failure could recur. Update all supported Android locale catalogs when adding translatable settings text. Fix the cause of CI failures and retain checks for APK signing, package identity, and version. For changes shared by multiple clients, verify each supported input form and keep matching rules generic.

## UI

- **Keep ReChord’s visual language.** Use its typography, glass surfaces, controls, touch targets, spacing, and theme colors. Borrow useful interaction patterns from other apps and adapt them to ReChord. Use short labels that describe what actually happens. Keep upstream credits in the README when their work informs a feature.
- **Design the loading state with the finished layout.** Use one stable skeleton matching the actual sections and dimensions. Show a coherent first layout. Populate optional artwork and Featured cards as they become ready without replacing the skeleton with a second placeholder layout or requiring users to leave and return. Keep the app usable when optional artwork or recommendations are slow or unavailable. Hidden items leave no spacer, skeleton, or dead controls.
- **Design every UI, logic, and animation change for Portrait, Landscape, DAPs, and Car Head-Units together — and keep all controls inside system safe areas.** Never design portrait-only and retrofit landscape later, and never alter Portrait geometry when fixing a Landscape-only layout issue. Verify Portrait phones (`360 × 800 dp`), Landscape phones with camera punch-holes/cutouts and gesture or 3-button side navigation bars (rotated both 90° and 270°), Portrait/Landscape DAPs (`720 × 1280 px` / `560–720 × 360 dp`), Car Head-Units (`640 × 360 dp` xhdpi, `800 × 480 dp`, `853 × 480 dp` hdpi, `1024 × 600 dp`, `1280 × 720 dp` mdpi), and Tablets (`1024 × 768 dp`). Enforce horizontal safe-area insets (`WindowInsets.navigationBars ∪ WindowInsets.displayCutout`, horizontal sides) at the Activity root (`horizontalSafeInsets`) **and** inside every separate `ModalBottomSheet` / `Dialog` window (`NowPlayingScreen`, `AlternateNowPlaying`, `PlaylistPickerSheet`, `ReplayStories`, `SongInfoDialog`, `AlertScaffold`) while letting full-bleed backgrounds/artwork paint behind system bars. In any landscape window (`width >= 560 dp && width > height`) with an active track, place `FloatingBottomBar` and `MiniPlayer` side by side (`<= 880 dp`, leaving free side strips on both edges) and cap `BottomFadeScrim` and `FloatingBarsTapGuard` to that bar width so side rails stay un-faded and tappable. Switch tall pickers and editors (`NowPlayingLayoutPicker`, `VinylAppearanceEditor`, `LocalTagEditorDialog`) to 2-column landscape layouts; scale horizontal transport rows (`AdaptivePlaybackPillRow`); bound popup/dialog scrollable bodies dynamically against `maxHeight` inside `safeDrawing` insets; and scope top sheet-handle overlays (`topHold`) in landscape so they never block taps on controls.
- **Scope controls to the feature.** Use the existing settings hierarchy and persist choices across launches. Apply Home visibility choices immediately and preserve the remaining shelf order. In both Home and Appearance → Home, keep recurring categories such as Recents, Quick Picks, Mixed for You, Daily Discover, Fresh Finds, Old Favorites, Listen Again, From Your Library, From the Community, Forgotten Favorites, and Featured Playlist. Their recommendations can change. Filter out one-off shelves dedicated to a specific artist, album, or release, including when older settings still reference those shelves. Keep Featured cards and their personalized recommendations.
- **Keep scrolling and tab switching flicker-free.** Use lazy lists and stable keys. Avoid disk reads, artwork decoding, network work, or fast-changing playback state at the list level. When changing list content and scroll offset together (such as switching Local Music pill tabs), call `LazyListState.requestScrollToItem` synchronously in the same state change rather than delaying `scrollToItem` across `LaunchedEffect` or `withFrameNanos` frames. Preserve section position during refresh and pause costly artwork effects where existing scroll or visibility handling supports it.
- **Keep Local Music browsable.** Permanently reserve a narrow right gutter (`32.dp`) whenever a Local Music list has an alphabetical index so rows and grid cards never shift horizontally when the A–Z rail fades in on scroll. In Portrait, end the A–Z rail cleanly above the mini-player; in Landscape side-by-side mode, extend it beside the centered bar row down to the bottom edge of the Now Playing pill, clear of bottom scrims and tap guards. Use the locale-aware index for accented letters and other scripts, and preserve the displayed name when sorting past a leading “The”. Keep Recently Added newest-first and capped at 100. Preserve Artist → Album → Tracks and the Album Artist view. Put library refresh in the existing menu.
- **Rasterize complex rotating artwork and avoid per-frame GPU allocations.** Compose `GraphicsLayer.record(...)` replays a vector DisplayList on every frame rather than caching a raster bitmap. Pre-bake patterned/textured vinyl finishes (`Marbled`, `Swirl`, `Galaxy`, `Glitter`, `Splatter`, `Smoked`, etc.) off the UI thread (`Dispatchers.Default`) into a bounded LRU `ImageBitmap` cache — including background pre-baking for `previousSong` and `nextSong` using immutable `track.videoId` seeds so async metadata backfills never redraw the texture — and rotate them as a single GPU quad. Flatten radially symmetric finishes into one static `CompositingStrategy.Offscreen` platter+grooves layer. Reuse cached shadow brushes via GPU `translate`/`scale`/`alpha` instead of allocating gradients inside `onDrawBehind`, and prefer layered zero-blur tonearm shadows over full-screen `BlurEffect` buffers. Never call `.dp.toPx()` inside `GraphicsLayer.record(...)` without passing `LocalDensity.current` (prevents `LayoutNodeDrawScope` ↔ `CanvasDrawScope` `StackOverflowError`).
- **Keep lifted discs solid, unclipped, and edge-to-edge in Landscape.** Keep lifted or swiping vinyl discs at `alpha = 1f` so drop shadows behind them never bleed through onto the vinyl surface. Apply drop-in transforms directly to the disc's own unbounded `2*radius × 2*radius` container so Portrait discs extending past `x < 0` are never vertically clipped. In Landscape, extend both Poster and Vinyl edge-to-edge under the status bar and bottom taskbar/nav bar (applying `WindowInsets.safeDrawing` only to the right-hand controls pane), align Poster's right-column hierarchy with Vinyl (bold title/credits → lyrics → 6-button controls → stats/volume/quality/actions), and avoid `.clipToBounds()` on the animated Vinyl stage.
- **Keep Settings alignment, text boundaries, and brand icons crisp.** Keep logically related Settings rows inside a single `SearchableSettingsGroup` card so sibling rows do not form pinched rounded corners. Align `SettingsSubRow` and inline sub-rows cleanly to `TEXT_INSET` inside icon cards (and omit phantom `ICON_GAP` on iconless rows). Enforce a minimum `16.dp` right-side gutter between every row's text column and trailing switches, values, or chevrons, and apply `TextOverflow.Ellipsis` to subtitles so text never collides with controls or truncates mid-comma. Keep the **Obsidian Vinyl R** icon assets aligned across `app`, `sharedUi`, `wearos`, adaptive foreground/background/monochrome XMLs, notification icons, and Play Store assets using closed filled vector paths.

## Logic

### Now Playing choreography, dock transitions, and frame budgets

- **Use a single source of truth for coupled animation state.** Never split coupled transitions (such as horizontal track swipe + vertical record lift/drop + tonearm clearance) across an immediate state holder and a `LaunchedEffect` — `LaunchedEffect` executes one frame after composition and causes 1-frame snap/bounce glitches. Derive Frame-1 promoted track offset, elevation, and `recordLanded` synchronously inside the swipe/turntable state holder (`AlternateTrackSwipe`).
- **Synchronize mini-player dock-flight animations across Portrait and Landscape.** In `PlayerDock.artworkInFlight`, ease out smoothly onto the live rising sheet position (`expandedOnScreen.translate(0f, offset)`) rather than compounding `offset` with linear `lerp` (which creates `f²` lag). Complete shape/curve masks (such as Poster's curved bottom edge) before the final `0.96..1.00` `liveCoverAlpha()` handoff so there is zero lag and zero double-image.
- **Follow physical turntable order on swipe and Next/Previous.** Clear the tonearm to the outer resting edge immediately on drag start or button press; lift the outgoing record smoothly off the platter and swap horizontally at lifted height; drop the incoming record straight down once centered over the spindle; and only after it is seated glide the tonearm to the groove, lower the needle, and begin visual spin (preserving instant/gapless audio behavior).
- **Scope touch targets to prevent mistouches.** Restrict Vinyl tonearm scrubbing to the headshell/cartridge head plus a generous outer halo so horizontal track swipes across the vinyl or tonearm shaft never accidentally trigger a seek. Keep top sheet-handle overlays scoped so they never intercept clicks on landscape controls.
- **Gate high-frequency clocks on visibility and active need.** Gate vinyl spin (`28°/sec` frame-accurate), Poster curved rim visualizer (~30–35 FPS), instrumental lyric dots, and word-synced lyric clocks on foreground visibility and active playback/need. Skip off-screen neighbor discs and artwork layers when idle, and cache per-screen-size Portrait vinyl geometry (`vinylMaxDiscBottom`) so expanding from the mini-player never redraws the vinyl texture.

### Playback, history, and audio output

- **Keep playback modes distinct.** Direct Source Stream should start with the lossless source when available, including cold resume from a nonzero position. Seamless Quality Upgrade may start promptly on its initial stream and upgrade in place. Reuse safe source lookup or prefetch where possible, without starting playback early.
- **Preserve the listener’s action and position.** Play and Shuffle should start the intended queue without cycling through tracks while source lookup is pending. Handle failure and retry at the responsible layer. Verify next track, seek, restart, and recovery across supported output paths.
- **Report the actual audio path.** Check built-in DAC, standard Android USB, Android 14 USB DAC, and USB Direct separately against their respective APIs. Keep source, decoder, resampler, sink, and hardware format claims tied to the active track and route. Verify sample-rate transitions in both directions, device reconnect, and fallback. Use **PCM Preserved** where supported by the actual path. Reserve **bit-perfect** for verified conditions. Avoid exposing internal failure codes as user-facing DAC copy.
- **Preserve YouTube Music history.** Signed-in, online playback with a YouTube video ID should continue reporting to the same account when the stream upgrades to lossless. Verify a qualifying play appears once and that watch time continues. Local files without a YouTube ID stay in on-device history. Keep local tracking independent of remote reporting failures.

- **Keep Autoplay behind the listener’s queue.** Continue the radio or recommendation context that started playback, including Featured **Play Picks**. Request more in bounded batches and deduplicate against the current queue. Resume after a late batch only when the same queue is still active and the listener intended playback to continue. Preserve manual queue order and the paused state.
- **Budget memory across players.** Prioritize the active player, budget standby and quality checks separately, and reduce read-ahead targets under heap pressure while allowing enough audio to start and recover. Retire old players before replacements load. Stop obsolete quality checks, defer optional AutoMix analysis under pressure, and bound artwork and Android Auto caches. Keep cache misses recoverable.
- **Keep the current audio in Convert to Video.** Synchronize the video to the active audio item, including when the displayed track points to a different catalog entry. Preserve audio source, format, position, playback intent, and queue. Keep the video silent while the original audio plays. Run independent video lookup and sync preparation concurrently when safe. Measure from the tap to the first visible frame and record the device and cache conditions before claiming a speedup. If video fails to load or synchronize, keep the audio session active and use the existing localized notice.
- **Keep add-on lookups compatible.** Send structured title and artist only when the add-on declares support and the fields are available. Keep the existing `q` request and app-side candidate assessment compatible with older and query-only add-ons. In Qobuz and MusicBrainz add-ons, use structured title and artist for the initial lookup and candidate comparison when available. Retain the existing `q`-only path and avoid adding a metadata retry pass. Rank and return up to 15 plausible candidates, filtering out obvious nonmatches and leaving the playback choice to the app. Verify both request forms with ReChord and a BitChord fork, including ambiguous titles and explicitly requested versions.

### Home, Explore, and Local Music

- **Build recommendations from existing listening.** Combine on-device ReChord history and signed-in YouTube Music history. Sample liked, recent, and frequent listening across artists, tracks, and albums. Give playlist membership a smaller, bounded boost and count duplicates once. Keep candidate lookup bounded and personalized features usable when one data source is unavailable.
- **Keep discovery distinct.** Try YouTube Music Related before radio and try alternate seeds when results are sparse. Prefer unheard tracks, cap repeat artists, and deduplicate across Featured cards and Daily Discover. Keep the visible carousel stable while browsing and rotate the picks on refresh.
- **Give each screen a purpose.** Featured highlights Continue Listening, releases from familiar artists, and a paged set of related song and artist recommendations. Let the amount of relevant, deduplicated content determine the card count. The image, label, and action must describe the same seed or selection. Home leads with Recently Played, Quick Picks, and Find Your Mood, then discovery, library, and community shelves. Top Songs and Trending default off. Music Videos, New Music Videos, and one-off promotions stay out of Home and its visibility controls. Explore carries the broader New Releases catalog, including unfamiliar artists.
- **Index local files incrementally.** Open Local Music from its index and add or update changed files without reloading the whole library on every visit. Use embedded track artwork first, then supported album-folder artwork such as cover, folder, or album JPEGs. Reuse cached thumbnails and a consistent fallback. Verify that external system playback surfaces can read published artwork.

- **Apply search and sort to the active view.** A Songs search returns track rows even when the query matches an album or artist. Sort each view by its own fields and build the alphabet jump index from the results actually displayed. Keep multi-disc tracks in disc and track order when browsing an album.
- **Resolve artist headers by identity.** Prefer a reliably matched artist image for Artist and Album Artist headers. Use representative local album artwork or the existing fallback when no suitable artist image is available.

### Diagnostics

- **Keep reports opt-in.** In **Settings → Diagnostics**, offer local export and direct submission when configured. Retain bounded, redacted crash and playback details for the next user-initiated report. Include useful numeric memory and audio-route details while excluding exception messages, personal data, credentials, signed URLs, and local paths.
- **Submit directly through the backend.** Keep GitHub credentials server-side. Confirm success only after the backend returns an issue number. Show submission failure in the app and keep export available.
- **Keep Now Playing → Copy Log track-scoped.** Copy the song, reported audio format, and recent ReChord playback and source events to the clipboard on demand. Preserve the bounded app-owned buffer, including events from prefetch for the same track. Avoid reading system logs, uploading from Copy Log, or exporting credentials and signed stream URLs.

## Delivery and verification

- **Respect approval and branch boundaries.** For investigation and plan-only requests, inspect and report. Implement the agreed scope after approval. Keep working on the named or current branch. Ask before creating or switching branches, and merge only when requested. Honor local-only and hold-CI instructions.
- **Deliver a testable build.** After an approved app implementation, verify locally with Gradle (`:sharedUi:jvmTest`, `:sharedUi:compileDebugKotlinAndroid`, `:app:compileDevDebugKotlin`, `:tv:compileDevDebugKotlin` when shared code or `BuildConfig` changes affect TV, and `:app:testDevDebugUnitTest --tests "com.music.bitchord.LocaleStringsTest"` whenever adding or renaming string keys in `app/src/main/res/values/strings.xml`), then commit and push on the agreed feature branch unless the task is local-only. Use the applicable Preview APK workflow (`ReChord Develop Preview APK`) and existing preview signing key unless the user asks to hold builds. Keep preview APKs arm64-v8a, separately installable from production, and **always uploaded as a single unzipped `.apk` file** (`actions/upload-artifact@v7` with `archive: false`) — never wrapped in a `.zip`. Verify the run targets the intended commit, and report its status (avoid polling CI logs unless requested).
- **Separate documentation delivery from APK delivery.** For documentation-only work, update the canonical guide and any affected agent instructions, check the diff and links, and commit to the agreed branch. Skip push-triggered builds (`[skip ci]`) for documentation-only changes unless the user requests a workflow.
- **Publish through develop and main when requested.** Confirm all approved changes are present, including app-side add-on support when applicable. Align `build.gradle.kts` (`bitchordVersionName` and `bitchordVersionCode`, with blank beta suffix) and `docs/releases/v<version>.md` for the exact GitHub tag. Write release notes in clear, friendly, non-technical language so everyday listeners immediately understand what is new (and note the upstream BitChord base version when a release includes an upstream sync), consolidating any superseded hotfix notes when requested. Merge through `develop` and `main` in that order. Respect any request to hold workflows through the merges. When authorized to run the release workflow, verify all triggered `main` workflows (`ReChord Signed Android Release`, `Check`, `TV`, `Contributors Image`) target the intended `main` commit, monitor them to completion, fix any issues that arise, and report their final status and published assets.
- **Keep published APKs stable.** Use the plain `v<version>` tag and release title for the first publication. Before choosing a tag, verify whether that version was already published. An unpublished or canceled build can be replaced by the first standard release. For a replacement after publication, retain the production signing key, increment the internal build number, and use a unique hotfix tag if the app version must stay the same. Preserve existing published APKs unless the user explicitly authorizes removing a hotfix release/tag and consolidating it into a newer version. Explain manual installation when the installed updater compares only version names.
- **Use representative verification.** Cover fresh installs (seeding new-install-only defaults via `prefs.all.isEmpty()` at the start of `AppSettings.init()` before migrations so upgrades preserve existing user settings) and upgrades with existing data, signed-in and signed-out states, offline or slow requests, and the affected playback and UI paths. For hardware or service behavior, use real devices and accounts when available. Clearly state what was verified with fixtures or an emulator and what still needs live verification.
