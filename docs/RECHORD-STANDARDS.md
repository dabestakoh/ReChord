# ReChord Engineering Standards

Canonical guide for planning and implementing ReChord changes. For upstream BitChord syncs, also follow [UPSTREAM-SYNC-POLICY.md](UPSTREAM-SYNC-POLICY.md) so intentionally omitted features are never pulled back in and ReChord's implementations take precedence.

## Coding

- **Investigate before editing.** Trace the real entry point, state owner, callers, and recovery path before changing code. Keep confirmed facts and hypotheses distinct.
- **Keep changes small, lean, and compatible.** Reuse existing Compose components, repositories, caches, queues, and settings patterns. Keep `MainActivity.BitChordApp` lean (extract helpers and collect feature flows in child screens to avoid JVM `Method too large` limits). Preserve existing user data, settings, indexes, playlists, history, package IDs, signing keys, and add-on compatibility. Seed new-install-only defaults via `prefs.all.isEmpty()` at the start of `AppSettings.init()` before migrations.
- **Keep async state safe.** Bound network fan-out, cancel obsolete requests, guard late results by active account/route/playback identity, retain valid cached data across transient failures, and isolate optional work from primary operations.
- **Verify regressions, imports, signatures & locales before running Gradle.** Before invoking Gradle, inspect `git diff` to confirm: (1) every newly used function, composable, or data class matches its exact verified signature; (2) every newly used symbol or extension function has its `import` in the modified file; and (3) no new inline lambdas or state were added to `MainActivity.BitChordApp` (extract top-level private helpers/composables). Then run the closest tests, add focused unit coverage for new logic, and update all 20 Android `strings.xml` locale catalogs whenever adding or renaming user-facing string keys.

## UI & Layout

- **Retain ReChord's UI template, visual look, and layout.** Always follow ReChord's established screens, typography, glass surfaces, cards, pills, spacing, touch targets, and artwork-derived theme colors. Reuse existing ReChord components and adapt new features cleanly into ReChord's layout — never drift into foreign UI templates or inconsistent visual styles. Use short, honest labels and keep upstream credits in `README.md`.
- **Every layout must honor all toggleable Settings automatically.** Proactively account for every Setting that can be turned off or changed — including **Reduce Liquid Glass** (`reduceDynamicBlur`, switching translucent glass controls to crisp solid high-contrast surfaces), **Reduce Motion** (`reduceAnimation`), **Light/Dark theme** (especially inside dark-styled surfaces like `InlineQueue`), **Autoplay**, **Lyrics/Stats/Volume bar visibility**, and **Home section visibility** — so no layout ever breaks, clips, or loses contrast when a setting is disabled.
- **Portrait, Landscape, DAP, Car Head-Unit & Tablet parity.** Design all form factors together: Portrait phones (`360 × 800 dp`), Landscape cutout/gesture/3-button-nav phones (both 90° and 270°), DAPs (`560–720 × 360 dp`), Car Head-Units (`640 × 360 dp`, `800 × 480 dp`, `853 × 480 dp`, `1024 × 600 dp`, `1280 × 720 dp`), and Tablets (`1024 × 768 dp`). Never break Portrait while fixing Landscape (or vice versa).
  - Enforce horizontal safe-area insets (`navigationBars ∪ displayCutout`, horizontal sides) at the Activity root (`horizontalSafeInsets`) **and** inside every separate `ModalBottomSheet` / `Dialog` window (`NowPlayingScreen`, `AlternateNowPlaying`, `PlaylistPickerSheet`, `ReplayStories`, `SongInfoDialog`, `AlertScaffold`) while letting full-bleed backgrounds paint behind system bars.
  - In landscape (`width >= 560 dp && width > height`) with an active track, place `FloatingBottomBar` and `MiniPlayer` side by side (`<= 880 dp`) and cap `BottomFadeScrim` / `FloatingBarsTapGuard` to that bar width so side rails stay un-faded and tappable.
  - Hide `FrostedTopBar` when a full-screen sub-mode (e.g. `ReorderPlaylistPage`) renders its own Close/Title/Save header so short landscape screens keep maximum vertical space.
  - Use 2-column landscape layouts for tall pickers/editors (`NowPlayingLayoutPicker`, `VinylAppearanceEditor`, `LocalTagEditorDialog`), scale horizontal transport rows (`AdaptivePlaybackPillRow`), bound scrollable dialog bodies against `maxHeight` inside `safeDrawing` insets, and scope landscape top sheet-handle overlays (`topHold`) so they never block controls.
- **Stable loading & flicker-free scrolling.** Match skeletons to the real layout without double-placeholder swaps; hidden items leave no gaps or dead controls. Use lazy lists with unique stable keys, avoid I/O or fast-changing playback reads at list level, and call `LazyListState.requestScrollToItem` synchronously when switching list content and scroll offset together (never delay via `LaunchedEffect` / `withFrameNanos`).
- **Local Music & A–Z index.** Permanently reserve a `32.dp` right gutter when an alphabetical index is present so rows/cards never shift on scroll. End the A–Z rail above the mini-player in Portrait and level with the Now Playing pill bottom in Landscape side-by-side mode. Keep locale-aware sorting (ignoring leading "The" while preserving display text), Recently Added newest-first (capped at 100), and Artist → Album → Tracks / Album Artist views.
- **Now Playing Vinyl, Poster & GPU efficiency.**
  - Pre-bake textured/patterned vinyl finishes off the UI thread (`Dispatchers.Default`) into a bounded LRU `ImageBitmap` cache keyed by immutable `track.videoId` (including `previousSong`/`nextSong`), rotating as a single GPU quad. Cache shadow brushes via `drawWithCache`, prefer zero-blur layered tonearm shadows, and pass `LocalDensity.current` inside `GraphicsLayer.record(...)`.
  - Keep lifted/swiping vinyl discs at `alpha = 1f` on unbounded `2*radius × 2*radius` containers. In Landscape, extend Poster and Vinyl edge-to-edge under system bars (`safeDrawing` on right controls pane only), align Poster's right-column hierarchy with Vinyl, and omit `.clipToBounds()` on the animated Vinyl stage.
  - Derive coupled swipe/lift/tonearm Frame-1 state synchronously in `AlternateTrackSwipe` (no `LaunchedEffect` desync). Synchronize `PlayerDock.artworkInFlight` to live sheet position (`expandedOnScreen.translate(0f, offset)`) and complete curve masks before `0.96..1.00` `liveCoverAlpha()`. Follow physical turntable order (clear tonearm → lift & swap → drop → land tonearm & spin, keeping audio instant/gapless). Restrict tonearm scrubbing to the headshell + outer halo, and gate spin/visualizer/lyric clocks on foreground visibility and active need.
- **Settings & branding.** Group related rows in one `SearchableSettingsGroup`, align `SettingsSubRow` to `TEXT_INSET` (no phantom `ICON_GAP` on iconless rows), enforce `>= 16.dp` gutter before trailing controls with `TextOverflow.Ellipsis` on subtitles, and keep **Obsidian Vinyl R** vector icons aligned across `app`, `sharedUi`, `wearos`, and store assets.

## Playback, Discovery & Diagnostics

- **Playback & audio paths.** Keep Direct Source Stream (lossless-first, including cold resume) and Seamless Quality Upgrade distinct. Preserve user queue, Play/Shuffle intent, manual queue order, and paused state (Autoplay appends bounded deduplicated batches behind manual queues). Report verified audio paths separately (built-in DAC, Android USB, Android 14 USB DAC, USB Direct), using **PCM Preserved** / **bit-perfect** only when verified and never surfacing internal error codes as DAC copy. Budget memory across players, retire old players before loading replacements, and keep Convert to Video synced to the active audio stream (silent video, preserving audio format/position and falling back gracefully).
- **YouTube Music history & add-ons.** Keep signed-in YouTube watch-history reporting intact across lossless upgrades while isolating Local Library files to on-device history. Send structured title/artist to add-ons only when declared supported, while preserving full compatibility with `q`-only add-ons (ranking up to 15 candidates).
- **Home, Explore & Local Music.** Blend on-device and signed-in YouTube history with bounded boosts, deduplicate across Featured and Daily Discover, keep Home's recurring shelves (filtering out one-off artist/album promotions and Music Videos), and leave broader New Releases in Explore. Index Local Music incrementally (embedded artwork first, then folder JPEGs) and scope search/sort/A–Z to the active view.
- **Diagnostics.** Keep crash/playback reports opt-in in **Settings → Diagnostics** with bounded, redacted logs (no credentials, signed URLs, or local paths) submitted through the backend (retaining local export). Keep **Now Playing → Copy Log** track-scoped and offline.

## Delivery & Verification

- **Approval & branches.** Stay read-only during planning until approved. Work on the current or named branch; ask before creating/switching branches; merge and release only when authorized.
- **Local verification before pushing.** Run `:shared:jvmTest`, `:sharedUi:jvmTest`, `:sharedUi:compileDebugKotlinAndroid`, `:app:compileDevDebugKotlin`, `:tv:compileDevDebugKotlin` (when shared code or `BuildConfig` affects TV), and `:app:testDevDebugUnitTest --tests "com.music.bitchord.LocaleStringsTest"` (when string keys change).
- **Preview APKs & docs.** Push approved code to the agreed branch (`preview-apk.yml` — `ReChord Preview APK` builds arm64-v8a separately installable APKs and **always uploads a single unzipped `.apk`** via `actions/upload-artifact@v7` with `archive: false`). Use `[skip ci]` for docs-only commits.
- **Signed releases on `main` (when authorized).** Update `build.gradle.kts` (`bitchordVersionCode`, `bitchordVersionName`, blank beta suffix), write plain-English user-facing `docs/releases/v<version>.md` (noting upstream BitChord base version when applicable), merge `develop` → `main`, monitor triggered `main` workflows (`ReChord Signed Android Release`, `ReChord Check`) to completion, and verify published release assets. Retain production signing keys and increment `bitchordVersionCode` on any replacement/hotfix build.
